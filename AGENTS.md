## Grove workflow

This repo uses grove: a phased, human-gated workflow for feature work.
Phases run in order, each producing a markdown artifact a human reviews
before the next phase starts:

1. **Questions** (`grove-questions`) — ticket/idea → scope, neutral research
   questions, size verdict.
2. **Research** (`grove-research`) — answers the research questions, facts
   about how the system works today.
3. **Design** (`grove-design`) — surfaces every one-way-door decision for
   explicit human choice.
4. **Structure** (`grove-structure`) — breaks the approved design into
   ordered, verifiable vertical slices.
5. **Plan** (`grove-plan`) — turns the approved structure into a detailed,
   agent-facing execution plan.
6. **Implement** (`grove-implement`) — executes the plan one slice at a
   time, stopping for human review after each slice unless run with `--all`.

Artifacts live at `docs/work/<feature-slug>/`:
`00-ticket.md`, `01-questions.md`, `02-research.md` (+ `.html`),
`03-design.md` (+ `.html`), `04-structure.md` (+ `.html`), `05-plan.md`,
`06-implementation.md`. `.html` companions are generated by `grove-render`
and never hand-edited.

### Gates

- Hard gates (block unless `--force <reason>`, recorded in `forced:`):
  `grove-structure` needs `03-design.md` approved; `grove-plan` needs
  `04-structure.md` approved; `grove-implement` needs both `04-structure.md`
  and `05-plan.md` approved.
- Soft gates (warn, proceed anyway): `grove-research` without approved
  `01-questions.md`; `grove-design` without approved `02-research.md`.
- Content gates (always enforced): no non-empty `## Open questions`, no
  `TODO`/`TBD`, every slice has a verification step, every design decision
  has a chosen option.
- Only `grove-approve`, invoked directly by a human, may set
  `status: approved`. No skill may invoke it on its own initiative.

See `shared/gates.md` and `shared/contract.md` for the full rules.
